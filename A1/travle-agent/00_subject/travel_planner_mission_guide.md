# [미션 가이드] LLM과 지도 API 조합을 통한 국내 여행 추천 프로그램 개발

본 가이드는 파이썬(Python)을 활용하여 다중 외부 API를 유기적으로 결합하고, 구조화된 데이터를 가공하여 가치 있는 엔드투엔드(End-to-End) 자동화 서비스를 구축하는 프로젝트 스펙 문서입니다.

---

## 1. 미션 배경 및 의의

현대 소프트웨어 아키텍처의 중심에는 **API(Application Programming Interface)** 가 있습니다. 개별 API는 독립적인 기능을 수행하는 격리된 모듈이지만, 여러 API를 조합하여 단일 워크플로우로 엮어낼 때 완전히 새로운 차원의 비즈니스 인사이트가 창출됩니다.

```
[사용자 입력: 날짜] 
       │
       ▼
 ┌───────────┐       도시 정보       ┌─────────────┐
 │  LLM API  │ ────────────────────> │  지도 API  │
 └───────────┘                       └─────────────┘
       │                                    │
 1차 추천 JSON                         맛집 정보 검색
       │                                    │
       └───────────────┬────────────────────┘
                       │
                       ▼
               ┌───────────┐
               │  LLM API  │ (최종 요약 및 일정 편성)
               └───────────┘
                       │
                       ▼
        [최종 산출물: Markdown 리포트]
```

본 미션은 단순히 단발성 API 호출에 그치지 않고, **AI의 추론 기능(LLM)** 과 **정형 데이터 검색 인프라(지도 API)** 를 결합하는 파이프라인 구조를 학습합니다. 1차 API의 구조화된 데이터 출력을 2차 API의 입력 매개변수로 정밀하게 매핑하고, 전체 과정에서 발생하는 예외를 탄력적으로 방어하는 견고한 데이터 연동 프로그램을 완성하는 것이 핵심 목표입니다.

## 2. 핵심 학습 목표 및 역량

프로젝트를 완료한 후, 학습자는 다음 네 가지 핵심 역량을 확보하고 면접이나 기술 검증에서 이를 명확하게 설명할 수 있어야 합니다.

1. **REST API의 요청/응답 구조 및 HTTP 메서드 명확한 이해**
   * 데이터 조회(GET)와 데이터 생성/처리(POST)의 네트워크 레이어 관점에서의 차이점.
   * HTTP Header, Query Parameter, Request Body의 올바른 활용법 및 인증 토큰 전달 매커니즘.
2. **LLM 출력의 구조화(Structured Outputs) 및 파이프라인 연동**
   * 비정형 텍스트를 출력하는 LLM에게 명확한 스키마 준수를 강제하고, 이를 JSON 데이터로 파싱하여 후속 시스템에 무결하게 바인딩하는 설계 기법.
3. **분산 외부 API 환경에서의 결합 방어 및 예외 처리 원칙**
   * 인증(401/403), 쿼터 초과(429), 네트워크 타임아웃, 포맷 파싱 에러 등 다차원적 실패 시나리오별 프로그램 생존 전략 수립.
4. **제로 트러스트(Zero Trust) 기반 API Credential 보안 관리**
   * 코드 저장소(Git) 유출 사고를 방지하기 위해 환경변수(`.env`) 시스템을 구축해야 하는 당위성과 배포 환경별 환경변수 관리 전략 체득.

## 3. 최종 산출물 규격

본 과제 완수 시 프로젝트 디렉토리 내부에는 다음과 같은 구조의 파일들이 완벽히 정비되어 있어야 합니다.

```
project_root/
│
├── travel_planner.py       # CLI 실행 진입점 (Main Script)
├── .env                    # API 핵심 키 관리 파일 (Git 제출 금지)
├── .gitignore              # .env 및 개발 캐시 제외 설정
├── requirements.txt        # 의존성 라이브러리 명세 목록
├── README.md               # 가이드라인 및 문제 해결 문서
│
└── results/                # 결과 저장 폴더 (자동 생성)
    ├── 2026-07-15_raw_data.json   # 1차 추천 및 지도 검색 데이터 원본 백업
    └── 2026-07-15_travel_plan.md  # 최종 렌더링된 마크다운 여행 리포트
```

### 3.1 CLI 기반 Python 프로그램 (`travel_planner.py`)
* **실행 인터페이스:** `argparse` 표준 라이브러리를 채택하여 커맨드라인 환경에서 명확한 인자값을 수용해야 합니다.
* **입력 형식:** `--date "YYYY-MM-DD"` 옵션을 필수로 입력받으며, 잘못된 날짜 형태 입력 시 명확한 에러 메시지와 사용법(Usage)을 표시하고 시스템을 안정적으로 조기 종료(`sys.exit()`)해야 합니다.
* **진행 로그:** 각 API 파이프라인 단계별 성공 유무, 탐색 결과 요약을 표준 출력(`stdout`)으로 보기 쉽게 출력해야 합니다.

### 3.2 실행 결과 데이터 (`results/` 디렉토리 하위)
1. **원본 데이터 JSON 파일:** 추후 디버깅과 데이터 정합성 검증을 위해 LLM이 반환한 1차 추천 객체와 지도 API를 통해 정제한 검색 결과 리스트, 그리고 실행 중 누적된 오류 기록(`errors`)을 하나의 타임스탬프 기반 JSON에 직렬화하여 기록합니다.
2. **최종 마크다운 리포트:** 최종 취합 데이터를 기반으로 LLM이 작성한 가독성 높은 마크다운 문서입니다.

### 3.3 프로젝트 README.md 규격
* **포함 사항:** 전체 아키텍처 개요, 가상환경 구성 및 의존성 패키지 설치 방법, 플랫폼별 환경변수 설정 가이드, 실행 커맨드 예시 및 결과 확인 방법.
* **보안 가이드:** 오픈소스 저장소에 API 키가 유출될 경우 발생할 수 있는 경제적·보안적 위협 시나리오와 예방 조치 명시.

## 4. 세부 기능 및 기술 요구사항

### 4.1 CLI 인터페이스 아키텍처
파이썬 내장 `argparse` 모듈을 사용하되, 입력값에 대한 데이터 정합성 검증 계층을 구현합니다. 정규표현식(`re` 모듈) 또는 `datetime.strptime` 함수를 활용해 사용자가 입력한 문자열이 실제 유효한 날짜 규격에 부합하는지 1차로 필터링해야 합니다.

```python
# 예시 검증 가이드 로직
import argparse
from datetime import datetime

def validate_date(date_string):
    try:
        return datetime.strptime(date_string, "%Y-%m-%d").date().isoformat()
    except ValueError:
        raise argparse.ArgumentTypeError(f"올바르지 않은 날짜 형식입니다: '{date_string}'. YYYY-MM-DD 규격을 준수하세요.")
```

### 4.2 LLM API 연동 엔진 (1차 엔진: 지역 및 정보 도출)
* **제공자 선택:** OpenAI 공식 라이브러리(`openai`) 또는 Google Gemini 라이브러리(`google-generativeai`) 중 하나를 택하여 개발합니다.
* **구조화 유도 프롬프트 설계:** 모델이 마크다운이나 불필요한 서론/결론 없이 오직 순수한 JSON 객체만을 응답하도록 페르소나와 제약사항을 설계합니다. OpenAI의 경우 `response_format={"type": "json_object"}` 옵션이나 Structured Outputs 기술을 사용하는 것을 권장합니다.

#### [1차 JSON 스펙 구성 표준]
```json
{
  "recommended_city": "강릉",
  "weather": "7월 중순은 평균 24°C~28°C 선으로 덥고 다습하며, 동해안 특성상 불시의 저기압성 강우 가능성이 상존함.",
  "events": ["경포 해변 페스티벌", "강릉 수제맥주 축제"],
  "reason": "여름철 동해의 시원한 풍광과 다채로운 해변 액티비티를 동시에 즐길 수 있는 최적의 시기입니다. KTX를 통한 접근성이 뛰어나 여름 휴가철 정체를 회피하기 좋습니다."
}
```

### 4.3 지도/장소 검색 API 연동 엔진 (2차 엔진: 맛집 소싱)
* **제공자 선택:** Kakao Local API(키워드로 장소 검색) 또는 Naver 검색 API(지역 검색) 중 연동 편의성이 높은 것을 채택합니다.
* **REST 통신 처리:** `requests` 라이브러리를 이용하여 엔드포인트에 동적 쿼리를 날립니다. 1차 단계에서 파싱된 `recommended_city` 문자열값과 검색 키워드(예: `"맛집"`)를 공백문자로 결합한 조합 키워드(예: `"강릉 맛집"`)를 파라미터로 송신합니다.
* **필수 취합 필드:** 식당명(`name`), 도로명 또는 지번 주소(`address`), 대분류 카테고리(`category`), 상세 페이지 정보 주소(`url`), 지도 공간 좌표 정보(`x`, `y` 또는 `lat`, `lng`).

### 4.4 최종 마크다운 리포트 생성 프로세스
1차 단계의 날씨, 행사 데이터와 2차 단계에서 수집된 맛집 리스트를 단일 프롬프트 컨텍스트로 취합합니다. LLM에게 해당 취합본을 제공한 뒤, 최종 사용자가 즉시 읽고 활용할 수 있는 형태의 미려한 **Markdown 보고서 문서** 작성을 명령합니다.

이때, 당일 이동 동선을 고려한 **'오전-오후-저녁' 단위의 1일 추천 일정 시나리오**를 인공지능이 자연스럽게 가미하도록 프롬프트를 고도화합니다.

## 5. 예외 처리 전략 및 견고함(Robustness) 유지 정책

시스템의 영속성을 위해 개별 통신 레이어마다 `try-except` 블록을 촘촘히 설계해야 합니다. 본 미션에서 통과해야 하는 결함 허용(Fault Tolerance) 매트릭스는 다음과 같습니다.

| 예외 시나리오 | 현상 분석 | 프로그램 조치 원칙 |
| :--- | :--- | :--- |
| **자격 증명 부재** | 환경변수 내 API 키 세팅 누락 | 즉시 프로세스 다운, 터미널에 콘솔 컬러나 명확한 문구로 `.env` 설정 지침 가이드라인 출력 |
| **지도 검색 결과 무(0건)** | 검색어 매칭 실패 또는 쿼리 오류 | 시스템을 정지시키지 않고 결과 리스트를 빈 배열(`[]`)로 설정. 최종 마크다운 리포트 해당 구역에 **"데이터 없음 (장소 검색 결과 0건)"**으로 마킹 후 흐름 유지 |
| **지도 API 인증 실패** | 401 Unauthorized / 403 Forbidden | 맛집 수집 기능을 바이패스(Bypass) 처리하고 `errors` 배열에 에러 기록 적재 후 리포트 빌드로 직행 |
| **LLM 응답 JSON 파싱 실패** | 불완전한 JSON 반환 혹은 스트링 유실 | 즉각적인 프로세스 킬을 방지하고, 예외 포착 즉시 프롬프트를 보정(예: "오직 유효한 JSON만 반환하라")하여 **최대 1회에 한해 재호출(Retry)** 수행 |

### 5.1 내부 오류 관리 스키마 (`errors` 리스트 구조)
프로그램 내부에 빈 리스트(`error_logs = []`)를 선언하고, 트래킹되는 시스템 예외 상황을 딕셔너리 형태로 실시간 추가(`append`)합니다. 해당 기록은 최종 JSON에 격리 저장되어 기술적 감사(Audit) 데이터로 기능합니다.

```json
"errors": [
  {
    "step": "place_search",
    "type": "AUTH_ERROR",
    "message": "HTTP 401 Unauthorized - 카카오/네이버 API 비밀키 권한 설정을 점검하십시오."
  }
]
```

## 6. 자격 증명 보안 정책 (Credential Security)

API 키는 금융 자산과 직결되는 민감한 비밀 자격 증명입니다. 소스코드 내부에 하드코딩하는 행위는 절대 엄금합니다.

### 6.1 `python-dotenv` 활용 메커니즘
프로젝트 루트 폴더에 `.env` 파일을 생성하고 키-값 쌍으로 선언합니다.

```ini
# .env 파일 보안 구성 예시
OPENAI_API_KEY=sk-proj-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
KAKAO_REST_API_KEY=4cxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

파이썬 코드 도입부에서 이를 로드하여 운영체제 내 물리적 메모리 환경변수로 안전하게 승격시켜 사용합니다.

```python
import os
from dotenv import load_model_data # 혹은 load_dotenv

load_dotenv()
openai_key = os.getenv("OPENAI_API_KEY")
if not openai_key:
    raise ValueError("Error: OPENAI_API_KEY가 세팅되지 않았습니다. 환경 설정을 점검하세요.")
```

## 7. 심화 과제 (Bonus Challenges)

과제의 핵심 요건을 조기 달성한 학습자는 다음 고도화 단계를 적용하여 아키텍처 역량을 강화할 수 있습니다.

### 7.1 복수 지역 추천 루프 설계 (Multi-City Expansion)
* **내용:** 1차 LLM 추천 단계를 확장하여 `recommended_cities: ["부산", "경주", "여수"]` 형태의 가변 배열 데이터를 반환받습니다.
* **도전 과제:** 파이썬 루프 제어문을 통해 각 도시별로 지도 API를 순회 호출(Fan-Out)하고 데이터를 집산(Aggregation)하는 데이터 핸들링 프로세스를 구축합니다.

### 7.2 결과 로컬 캐싱(Caching) 시스템 도입
* **내용:** 동일한 날짜 매개변수로 반복 실행 시 무분별한 API 과금 및 네트워크 레이턴시가 발생하는 문제를 방지합니다.
* **도전 과제:** 실행 타깃 날짜에 부합하는 파일(`results/{DATE}_raw_data.json`)이 로컬 디스크 상에 이미 존재하는지 조회한 뒤, 파일이 유효하다면 외부 네트워크 원격 호출을 즉시 생략(Skip)하고 로컬 스토리지의 정적 스냅샷 데이터를 즉각 역직렬화하여 리포트를 고속으로 재생성해내는 멱등성(Idempotency) 로직을 완성합니다.
