요건 01

REST API 연동

다중 외부 API를 유기적으로 결합해 엔드투엔드 자동화 파이프라인을 구축한다.

요건 02

LLM 구조화 출력

LLM에게 스키마를 강제하고, JSON 파싱 실패 시 1회 재시도하는 견고한 연동을 구현한다.

요건 03

예외 처리 (Fault Tolerance)

401/403/429/타임아웃 등 다차원 실패 시나리오에서 파이프라인이 살아남고 errors[]에 기록한다.

요건 04

보안 — Zero Trust

모든 API 키는 .env에만 보관. 코드·저장소 어디에도 하드코딩 금지.

파이프라인 구현
[--date YYYY-MM-DD] │ ▼ ① weather.py — Open-Meteo Climate API 11개 도시 × (월일 ±3일 평균기온·습도) → comfort_score = temp_score×0.6 + hum_score×0.4 → 최고 점수 도시 선정 (결정론적, LLM 미사용) │ ├─ ② tour.py — TourAPI KorService2 │ searchFestival2 (당월 1일~, 기간 내 필터) │ searchStay2 (지역코드 기반, 10건) │ ├─ ③ places.py — Kakao Local │ "{도시명} 맛집" + category_group_code=FD6 │ └─ ④ llm.py — OpenRouter → Gemini-2.5-flash 수집 데이터 → 오전/오후/저녁 마크다운 리포트 파싱 실패 시 1회 재시도 │ ▼ results/{DATE}_raw_data.json results/{DATE}_travel_plan.md │ ▼ (재실행 시) [캐시 HIT] → API·LLM 생략, 기존 파일 즉시 반환
사용 API
서비스용도비고
Open-Meteo Climate 11개 도시 기후 평년값 (기온·습도) API 키 불필요. 기준연도 2000, ±3일 윈도우 평균.
TourAPI KorService2 축제(searchFestival2), 숙박(searchStay2) 공공데이터포털 인증키. 범용 함수로 엔드포인트 분리.
Kakao Local 맛집 키워드 검색 REST API 키. FD6 카테고리 필터.
OpenRouter → Gemini-2.5-flash 마크다운 리포트 생성 LLM은 마지막 단계에서만 사용. 실패 시 폴백 반환.
