01 · 서비스 목적

왜 만드는가

Teenage Engineering의 장비들(EP-133, OP-1 Field, TX-6)은 독창적인 디자인만큼 사용법이 직관적이지 않습니다. 공식 매뉴얼은 영문 PDF로 수십 페이지에 달하며, 원하는 정보를 찾는 것 자체가 장벽이 됩니다.

Synth Agent는 이 장벽을 없앱니다. 자연어로 질문하면 매뉴얼 내용을 기반으로 정확하게 답변하고, 단계별 튜토리얼로 컨트롤을 직접 익힐 수 있습니다.

문제

영문 PDF 매뉴얼, 복잡한 버튼 조합, 찾기 어려운 기능 설명

해결

한국어 AI 챗봇이 매뉴얼 내용을 즉시 안내. 단계별 인터랙티브 튜토리얼 제공

가치

장비를 처음 꺼내는 순간부터 음악 제작에 집중할 수 있는 경험

04 · 핵심 기능

무엇을 할 수 있는가

장비 전환
헤더 드롭다운으로 EP-133 · OP-1 Field · TX-6 간 전환. 전환 시 AI 대화 초기화, 튜토리얼 목록과 다이어그램이 해당 장비로 교체됨.
AI 챗봇
OpenRouter API(claude-3-haiku) 기반. 장비별 매뉴얼 내용을 시스템 프롬프트로 주입. SSE 스트리밍으로 실시간 출력. 컨트롤 이름은 오렌지 볼드(**SAMPLE**)로 강조.
추천 질문
AI 모드 첫 진입 시 장비별 추천 질문 1개 표시. 답변 완료 후 후속 질문 3개 칩으로 자동 제안. 클릭하면 즉시 전송.
인터랙티브 튜토리얼
스텝 진행 시 좌측 장비 다이어그램의 해당 버튼에 오렌지 하이라이트 표시. 세그먼트 진행 바, 이전/다음 내비게이션. "이렇게 보이거나 들려야 해요" 확인 박스 포함.
반응형 UI
모바일에서 장비 패널 숨김, 단일 열 레이아웃. 헤더 텍스트 축소. 입력 영역 패딩 조정. md: 브레이크포인트 기준(768px).
대화 관리
하단 "clear" 버튼으로 대화 히스토리 초기화. 초기화 시 API 전달 메시지 배열도 함께 리셋. 다중 턴 문맥 유지(이전 답변 참조 가능).

05 · AI 기능 명세

AI 기능 입력 · 출력 · 실패 처리

AI 챗봇의 동작 기준을 입력, 출력, 실패 처리 세 영역으로 명세합니다.

입력 (Input)
  • 사용자 메시지: 자유 형식 한국어 텍스트. 제한 없음.
  • 장비 컨텍스트: 현재 선택된 장비 슬러그(ep-133 / op-1f / tx-6)가 요청에 포함. 백엔드가 해당 장비의 매뉴얼 내용을 시스템 프롬프트로 주입.
  • 대화 히스토리: 이전 user/assistant 메시지 배열 전체를 API에 전달. 문맥 기반 답변 가능.
  • 초기 추천 요청: messages: [] 빈 배열로 POST 시 추천 질문 1개 반환 (스트리밍 없음).
  • 최대 토큰: 요청당 max_tokens: 1200.
출력 (Output)
  • 스트리밍 방식: Server-Sent Events(SSE). data: {"type":"chunk","text":"..."} 이벤트가 텍스트 조각 단위로 전송됨. 사용자는 첫 단어부터 즉시 확인.
  • 완료 이벤트: 스트림 종료 시 data: {"type":"done","heading":"...","suggestions":[...],"tags":[...]} 전송. 이 시점에 제목, 후속 질문 3개, 태그가 화면에 표시됨.
  • 텍스트 포맷: 컨트롤 이름은 **BUTTON** 마크다운. 번호 목록(1. ), 불릿(- ) 지원. 프론트엔드가 파싱해 오렌지 볼드, 리스트로 렌더링.
  • 메타데이터 분리: 모델 출력에서 |||META||| 구분자 이후를 JSON으로 파싱. 구분자 이전만 화면에 표시.
  • 언어: 항상 한국어 답변. 시스템 프롬프트에 명시.
실패 처리 (Error Handling)
  • API 키 미설정: 백엔드에서 OPENROUTER_API_KEY 환경 변수 없으면 OpenRouter 401 오류 반환. 프론트에 {"type":"error","error":"OpenRouter 401: ..."} 이벤트 전송. 채팅창에 "오류: ..." 표시.
  • 네트워크 오류: fetch 자체가 실패하면 catch 블록에서 "잠시 후 다시 시도해 주세요." 메시지와 "연결 오류" 제목 표시.
  • 스트림 중단: 스트리밍 도중 연결이 끊기면 이미 수신한 내용까지만 표시. done 이벤트 미수신 시 heading/suggestions 없이 콘텐츠만 표시됨.
  • 메타데이터 파싱 실패: |||META||| 이후 JSON 파싱 실패 시 {} 처리. heading은 기본값 "답변", suggestions/tags는 빈 배열로 폴백.
  • 부분 구분자 노출 방지: 스트리밍 중 |||META|||가 여러 청크로 분리되어 도착할 경우, 구분자가 될 수 있는 끝 문자열을 보류(holdback)하여 화면 노출 차단.
  • 로딩 상태: 응답 대기 중 스켈레톤 UI + 깜빡이는 커서 표시. 전송 버튼 비활성화로 중복 요청 방지.

AI 요청 흐름

Step 1

프론트엔드 → 백엔드

React/JS가 POST /api/chat에 {messages, deviceSlug} 전송. 스트리밍 응답을 ReadableStream으로 수신 준비.

Step 2

백엔드 → OpenRouter

Flask가 장비 매뉴얼을 시스템 프롬프트로 조합해 OpenRouter API(claude-3-haiku)에 스트리밍 요청.

Step 3

스트리밍 청크 전달

OpenRouter가 청크를 보낼 때마다 |||META||| 여부를 확인. 메타데이터 이전 내용만 chunk 이벤트로 프론트에 전달.

Step 4

완료 이벤트

전체 스트림 수신 완료 후 메타데이터 JSON 파싱. done 이벤트로 heading, suggestions, tags 전송.

Step 5

화면 업데이트 완료

제목, 태그, 후속 질문 3개가 답변 아래에 표시. 다음 입력 대기 상태로 전환.
